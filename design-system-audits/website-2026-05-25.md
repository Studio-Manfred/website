# Design system audit: studiomanfred.com (whole website)

**Date**: 2026-05-25
**Scope**: `app/`, `components/`, `lib/`, `app/globals.css` — `main` @ `21adee4`
**Linear ticket**: filed as STU-? (Web project, see below)
**Auditor**: Jens Wedin (via Claude)
**DS version consumed**: `@studio-manfred/manfred-design-system` 0.22.0

## TL;DR

The website is **consuming 3–4 of ~99 DS components** and **0 of the layout primitives**. Most over-overriding traces back to one root cause: `components/ds.tsx` only re-exports `Button / Container / Logo / Typography`, so every other DS surface is structurally unreachable from the site code. Typography is re-exported but **never used in JSX** — every heading hand-rolls weight + leading + tracking instead.

No block-merge findings — the site builds, renders, and passes axe in CI. All findings are backlog work.

## High-priority backlog

### 1. `components/ds.tsx` re-export surface caps the ceiling

[components/ds.tsx](../components/ds.tsx) re-exports **only** `Button, Container, Logo, Typography`. Every other DS surface is structurally unreachable from any consumer that follows the project's "import DS primitives via `@/components/ds`" rule (CLAUDE.md).

This is the **root cause** of findings 2–4. Fix: widen the re-export to include Typography variants, Stack / HStack / VStack / Grid, Accordion family, PageBackground / PageShell, Card / Badge / Separator on demand. The DS is already a single bundled "use client" entry so there's no client-boundary penalty.

**Recommended fix**: open a follow-up ticket to widen `components/ds.tsx`.

### 2. DS Typography component is never consumed

Every heading in the site hand-rolls weight + leading + tracking even though DS `Typography` ships `headline1..4 / large / body / bodySmall / label / caption` variants that already encode `font-extrabold`, `leading-[1.1]`, `tracking-[-0.02em]`, etc.

Examples of hand-rolled headings that could be `<Typography variant="headlineN">`:
- [components/sections/Hero.tsx:23-29](../components/sections/Hero.tsx#L23-L29) — `<h1 className="font-extrabold leading-[var(--line-height-tight)] tracking-[var(--letter-spacing-tight)] ...">`
- [components/sections/Services.tsx:8-14](../components/sections/Services.tsx#L8-L14) — `<h2 className="font-extrabold leading-[var(--line-height-tight)] tracking-[var(--letter-spacing-tight)] text-[var(--color-business-blue)] mb-12 md:mb-16">`
- [components/sections/WhatElse.tsx:11-15](../components/sections/WhatElse.tsx#L11-L15) — same shape
- [components/sections/JoinUs.tsx:11-15](../components/sections/JoinUs.tsx#L11-L15) — same shape
- [components/sections/WritingHeader.tsx:11-19](../components/sections/WritingHeader.tsx#L11-L19) — same shape
- [components/sections/WritingListItem.tsx:28-35](../components/sections/WritingListItem.tsx#L28-L35) — same shape
- [app/training-and-courses/page.tsx:55-58](../app/training-and-courses/page.tsx#L55-L58) — same shape
- [app/join-us/page.tsx:215](../app/join-us/page.tsx#L215), [224](../app/join-us/page.tsx#L224), [320](../app/join-us/page.tsx#L320) — `<h3>` / `<h4>` with inline `fontSize: clamp(...)`

**Tension**: DS Typography variants use **static** sizes (`text-[3.5rem]` etc.), but the website wants `clamp(...)`. The cheapest fix is `<Typography variant="headline1" className="text-[clamp(...)]">` (variant ships everything except the size). The cleanest fix is a DS-side ticket to add fluid headline variants — see Cleanup §3.

### 3. DS Accordion not consumed — training page hand-rolls one

[app/training-and-courses/page.tsx:41-90+](../app/training-and-courses/page.tsx#L41-L90) hand-rolls an accordion with `useState`, manual `aria-expanded`, manual `aria-controls`, manual `<button>` styling, manual `+`/`×` icon rotation, manual `maxHeight` transition.

DS 0.22.0 exports `Accordion / AccordionItem / AccordionTrigger / AccordionContent` (Radix-backed, ARIA handled). Migrating saves ~40 lines and removes the only "blue background + peach borders" custom panel logic on the site.

### 4. DS layout primitives never used — 0 imports of HStack / VStack / Stack / Grid

[app/join-us/page.tsx](../app/join-us/page.tsx) alone has **71 inline `style={{ ... }}` occurrences** (12% of all 580 lines), most of which are layout composition — gaps, flex direction, alignment. The DS layout primitives encode these as props.

Distribution of top inline-style consumers:

| File | inline `style={{ }}` | arbitrary `[var(--...)]` |
| --- | --- | --- |
| `app/join-us/page.tsx` | 71 | 51 |
| `components/CourseDetail.tsx` | 26 | 26 |
| `components/sections/Team.tsx` | 13 | – (rave palette — justified, see Cleanup §1) |
| `app/training-and-courses/page.tsx` | 10 | 4 |
| `app/privacy-policy/page.tsx` | 5 | 8 |

`app/join-us/page.tsx` is the standout — 580 lines of inline JSX that pre-dates the Section primitive (STU-316 didn't reach the inner cards). Worth a dedicated migration ticket.

### 5. `#f5f3ee` cream hex literal in three places — DS has `--color-cream`

- [app/join-us/page.tsx:198](../app/join-us/page.tsx#L198) — `bg: "#f5f3ee"`
- [app/join-us/page.tsx:204](../app/join-us/page.tsx#L204) — `bg: "#f5f3ee"`
- [app/join-us/page.tsx:279](../app/join-us/page.tsx#L279) — `style={{ backgroundColor: "#f5f3ee", ... }}`

DS ships `--color-cream` and the Section primitive supports `background="cream"`. Direct token-bypass; replace with `var(--color-cream)` (or, if these become Section-wrapped, `background="cream"`).

### 6. `<main>` boilerplate repeated in 7 routes — DS ships PageShell / PageBackground

`<main id="main" tabIndex={-1}>` (and three variations with `cursor-white bg-[var(--color-business-blue)] min-h-screen`) appears in 9 places across the codebase. The DS exports `PageBackground` / `PageShell` for exactly this — variant-based surfaces, root element configurable, integrates with the skip-link landing pattern.

This is the lowest-leverage of the six — the current pattern works and the a11y baseline (id="main", tabIndex={-1}) is intact — but it's the most repetitive single bit of boilerplate in the codebase.

## Cleanup

### 1. `components/Marquee.tsx` canvas-drawn hex literals

[components/Marquee.tsx:126](../components/Marquee.tsx#L126) — `ctx.fillStyle = g.isWave ? "#2c28ec" : "#1e1e24";`

Canvas drawing can't consume CSS vars directly, but it can read them once via `getComputedStyle(document.documentElement).getPropertyValue('--color-business-blue').trim()`. Worth doing on the next Marquee touch so a token rename doesn't desync the canvas.

### 2. `lib/typography.ts` shadows DS `fontSize` export

The DS exports `fontSize: { xs, sm, md, lg, xl, 2xl, 3xl, 4xl, 5xl }` as **static** sizes. The website's [lib/typography.ts](../lib/typography.ts) also exports `fontSize` — but its values are `clamp(...)` strings for fluid type. Same name, very different shape. Worth renaming to `fontSizeFluid` (or `fluidType`) to avoid the trap of a contributor doing `import { fontSize } from "@/lib/typography"` when they meant the DS scale (or vice versa).

### 3. DS gap: Typography variants are static, not fluid

Caller signal: every consumer that uses `Typography` would still pass `className="text-[clamp(...)]"` to make headlines responsive. That's a DS-side gap, not a website bug — file in the DS project for v0.23 to ship `headline1Fluid..headline4Fluid` (or a `fluid` prop). Pair this with finding §2 — if fluid variants land, the website's wholesale Typography migration becomes pure subtraction.
